A widget template is JSON, not code. Five node forms — text, `bind`, element, `each` and `when` — compile into an ordinary renderer, and every value that reaches the output is either one of your literals or payload data rendered as escaped text. The one exception, a Markdown text bind, wraps that text in a fixed set of elements its parser chooses. There are no expressions: data *selects*, and you supply every literal. This page is the human version of the rules; the generated [Template DSL reference](/reference/template-dsl) and [Limits](/reference/limits) carry the exact lists and numbers.

## Node forms

<Tabs>
<Tab title="Text and bind">
A string is a text node. `{ "bind": "path" }` renders the value at that path as text; `"."` binds the current scope itself.

```json
{ "tag": "span", "children": ["Customer: ", { "bind": "customer.name" }] }
```
</Tab>
<Tab title="Element">
`{ "tag", "attrs"?, "children"? }`. Attribute values are strings or `{ "bind" }` objects.

```json
{ "tag": "a", "attrs": { "class": "wg-link", "title": { "bind": "label" } }, "children": [{ "bind": "label" }] }
```
</Tab>
<Tab title="Each">
Repeats `template` once per array element, with the element as scope. `empty` renders when the array is missing or empty. The optional `key` names the item path that identifies each element, such as an `id` or a SKU. When an action re-renders the list in a different order, each item's element moves with it and keeps its state, such as a disclosure the reader opened. Without a key, elements are reused by position. A key adds nothing to the output.

```json
{
  "each": "lines",
  "key": "sku",
  "template": { "tag": "li", "children": [{ "bind": "item" }, ": ", { "bind": "amount" }] },
  "empty": "No line items."
}
```
</Tab>
<Tab title="When">
Renders `template` when the path resolves truthy, otherwise `else` (or nothing).

```json
{
  "when": "paid",
  "template": { "tag": "span", "attrs": { "class": "wg-status wg-status-success" }, "children": ["Paid"] },
  "else": { "tag": "span", "attrs": { "class": "wg-status wg-status-warning" }, "children": ["Open"] }
}
```
</Tab>
</Tabs>

### Value transforms

A bound attribute value may carry one transform — `map`, `prefix` or `format`, never two. A text bind carries one of `map` (with its optional `default`), `format` or `markdown: true`; `prefix` is for attribute values only.

`map` lets a data value select one of your literals. A hit emits that key's literal; a miss emits `default`, or an empty value without one. Data never contributes output characters.

```json
{
  "tag": "span",
  "attrs": {
    "class": {
      "bind": "status",
      "map": { "do-not-contact": "wg-status wg-status-danger", "active": "wg-status wg-status-success" },
      "default": "wg-status"
    }
  },
  "children": [{ "bind": "status" }]
}
```

`prefix` emits your literal followed by the bound value, but only when that value is a non-empty string, so an absent email yields no dead `mailto:` link.

```json
{ "tag": "a", "attrs": { "href": { "bind": "email", "prefix": "mailto:" } }, "children": [{ "bind": "email" }] }
```

The value is percent-encoded, and your prefix alone decides how:

| Prefix | The value is | Example |
|---|---|---|
| Anything longer than a scheme (`https://api.dicebear.com/9.x/initials/svg?seed=`, `https://cdn.example.com/u/`) | one URI component, encoded as `encodeURIComponent` does, so it cannot add parameters, a fragment or a path segment | `Ada & Lin?x=1` → `…?seed=Ada%20%26%20Lin%3Fx%3D1` |
| A bare scheme other than the web ones and `data:` (`mailto:`, `tel:`) | the scheme's address: letters, digits and `-._~@+:;,=!$'()*/` stay, everything else is encoded, so it cannot add header fields or a fragment | `ada@example.org` stays; `ada@example.org?subject=hi` → `ada@example.org%3Fsubject=hi`; `+1 555-0100` → `+1%20555-0100` |
| Exactly `http:`, `https:`, `http://` or `https://` | the rest of a URL: spaces, control characters, double quotes, angle brackets, the backslash, caret, backtick, braces, the vertical bar and non-ASCII are encoded, and every delimiter stays, so the value chooses the host, path and query as a whole bound URL does | `//cdn.example.com/a b.png?w=1&h=2` behind `https:` → `https://cdn.example.com/a%20b.png?w=1&h=2` |
| Starting with `data:` (`data:image/png;base64,`) | kept as written: the guard admits only a base64 image source | `iVBORw0KGgo=` → `data:image/png;base64,iVBORw0KGgo=` |

Non-ASCII characters are encoded as UTF-8 (`José` → `Jos%C3%A9`). Pass raw values: an already-encoded value behind a component prefix is encoded again. A value with `/` behind a path prefix becomes one segment (`a/b` → `a%2Fb`); to compose several segments, bind the whole URL instead.

`format` presents a value at render time while the payload keeps its typed value — the same placement rule the built-ins' `hints.fieldFormat` follows. The vocabulary is closed and data-only: `number` and `currency` (bounded decimals, an ISO-4217 code, an optional `currencyDisplay` and `locale`), `date` (a pattern of the tokens `yyyy MM dd HH mm ss` plus separators) and the text formats below. Numeric strings parse, so the ten-decimal price strings a JSON API returns present as money; a value the format cannot parse renders raw, so a format never hides data.

```json
{
  "tag": "li",
  "children": [
    { "bind": "ask", "format": { "type": "currency", "currency": "COP", "decimals": 0 } },
    " @ ",
    { "bind": "date", "format": { "type": "date", "pattern": "dd-MM-yyyy HH:mm" } }
  ]
}
```

Against `{ "ask": "3206.9905920000", "date": "2026-09-01T02:04:47.257871358" }` that renders `$3,207 @ 01-09-2026 02:04`. An unzoned timestamp is read as UTC and formatted in UTC, and the default locale is fixed at `en-US`, so a server render, a designer preview and an action's re-render agree byte for byte — anything else would make the in-place patcher see phantom text changes.

The text formats present lists and text under the same rules. `count` renders an array's length, grouped (`1,234`). `join` joins an array's items with `separator` (default `", "`), puts the optional `last` before the final item, and with `field`, a plain dotted path such as `owner.name`, reads that path in each item; null and empty items are skipped. `truncate` keeps `length` code points (1 to 1000) and appends `ellipsis` (default `…`) when it cuts. `pluralize` picks one of its `forms`, keyed by plural category (`zero`, `one`, `two`, `few`, `many`, `other`; `other` is required), and replaces `{count}` with the grouped number. It reads a number, a numeric string or an array's length, uses a `zero` form for exactly 0, and otherwise follows the locale's plural rules. `count` and `pluralize` take an optional `locale`.

```json
{ "bind": "colors", "format": { "type": "join", "last": " and " } }
```

Against `{ "colors": ["red", "green", "blue"] }` that renders `red, green and blue`.

### Markdown text binds

`{ "bind": "notes", "markdown": true }` renders a text value as a small Markdown subset: paragraphs separated by blank lines, line breaks, `*em*` or `_em_`, `**strong**`, inline code, `[links](url)`, and flat `- ` or `1. ` lists (an ordered list keeps its starting number). Everything else stays literal text, so no data is hidden: headings, code fences, block quotes, images, tables and raw HTML. The parser, not the value, chooses the elements. The output is one `div.wg-md` holding only `p`, `br`, `strong`, `em`, `code`, `a`, `ul`, `ol` and `li`; every character of the value is emitted as text; and a link's URL faces the same scheme guard as a bound `href`, so a refused link renders as its text. A value over 20,000 characters renders as one plain paragraph without parsing.

```json
{ "tag": "div", "children": [{ "bind": "notes", "markdown": true }] }
```

Against `{ "notes": "Ship **Friday**.\n\n- review\n- merge" }` the `div` holds `<div class="wg-md"><p>Ship <strong>Friday</strong>.</p><ul><li>review</li><li>merge</li></ul></div>`. Every element and text the parser emits spends the render's node budget. Place the bind in a block container, a `div` rather than a `span`, and restyle the output with `.wg-md` selectors such as `.wg-md p`. The base stylesheet already spaces paragraphs, indents lists, sets code in the monospace font and colors links with the accent.

## Paths

Paths are dot notation against `payload.data`: `items.0.name` walks objects and array indices. Inside `each`, the scope is the current element. Four escapes exist:

| Path | Resolves against |
|---|---|
| `$meta.title` | `payload.meta` |
| `$root.owner` | the top-level data, from any `each` depth |
| `$parent.name` | one enclosing `each` scope out; repeatable as `$parent.$parent.x` |
| `$index` | the zero-based position in the innermost `each` |

Missing or non-traversable paths are blanks, not errors: empty text for `bind`, no repetitions for `each`, the `else` branch for `when`. Interpretation never throws, whatever shape the data has.

<Tip>
Bind properties your `dataSchema` declares. Schema-declared data is validated with dotted paths, so an agent gets a correctable error instead of blank output. `$meta.*` is outside schema validation; if the widget needs a heading, declare `title` as an optional property instead. See [Data schemas](/design/data-schemas).
</Tip>

## What a template cannot do

- **Run code.** There are no expressions, functions or scripts. Bound values are never parsed as HTML: a bound value of `<img onerror=x src=y>` renders as those literal characters, not as an element. The one bind that emits elements is a [Markdown text bind](#markdown-text-binds), and there the parser, not the value, chooses them: only `p`, `br`, `strong`, `em`, `code`, `a`, `ul`, `ol` and `li` inside one `div.wg-md`, links face the `href` scheme guard, and raw HTML in the value stays text.
- **Attach handlers.** Attribute names matching `on*` fail validation with `FORBIDDEN_ATTRIBUTE`, as do `srcdoc` and the renderer-reserved `data-wg-*` names. They are skipped at render time as well.
- **Embed active content.** `script`, `iframe`, `frame`, `frameset`, `object`, `embed`, `style`, `link`, `meta`, `base`, `template` and `noscript` fail with `FORBIDDEN_TAG`.
- **Smuggle URL schemes.** On URL-bearing attributes (`href`, `src`, `action`, `formaction`, `xlink:href`, `data`, `poster`, `ping`) only `http`, `https`, `mailto`, `tel` and relative references survive; anything else, `javascript:` included, is dropped at render time. A `prefix` value runs the same guard, so `"prefix": "javascript:"` is dropped like a bound `javascript:` value, and behind a scheme-less prefix the encoded value cannot add a scheme (its `:` becomes `%3A`).
- **Use `data:` URIs**, with one exception: an `img` element's `src` accepts base64 `data:image/*;base64,` URIs.
- **Nest without limit or render without bound.** Validation rejects nesting past a fixed depth (`TEMPLATE_TOO_DEEP`); interpretation stops at a node budget and marks the render truncated, because `each` multiplies template nodes by agent-supplied data length and a Markdown bind emits nodes in proportion to its value. The numbers are in [Limits](/reference/limits).

## Validation errors

`validateTemplate` returns a structured error with a `code` (`INVALID_TEMPLATE_NODE`, `INVALID_PATH`, `FORBIDDEN_ATTRIBUTE`, `FORBIDDEN_TAG`, `TEMPLATE_TOO_DEEP`, `INVALID_ACTION` or `CONFLICTING_ATTRIBUTES`), a message, and a dotted `path` locating the node, such as `children.0`. The designer shows it at the offending node; the store refuses the entry on write.

## Roots and wrapping

When the root interprets to anything but exactly one node (an `each` at the root, for instance), the output is wrapped in a `div` with class `wg-template`. A single element root is emitted as is.

Elements may also carry an `action` binding: a `button` or `a` bound to a `prompt` or `http` action, never together with `href`. That form is covered in [Actions and secrets](/design/actions-and-secrets).
