## MODIFIED Requirements

### Requirement: Reference pages are derived, never restated
The Reference tab's pages for the authoring contract (entry shapes, template DSL forms and safety rules, identifier rules, style and schema constraints, limits), the theme tokens (every token with type, use and default; the light defaults and the `dark` preset), the action definition (kinds, binding forms, scope semantics, the method/output-mode/name/length vocabulary), the MCP tools (every published tool definition — name, description, input schema) and the export index of every published package entry SHALL be generated by `npm run docs:generate` from the exported constants and validators (`buildAuthoringGuide()` including its `actions` section, `TOKEN_SPECS`, `TOKEN_DEFAULTS`, `darkTheme`, `HTTP_METHODS`, `OUTPUT_MODES`, `PROMPT_TEXT_MAX`, `SECRET_NAME`, `ACTION_NAME`, the `*_TOOL` definitions, the entries' runtime exports) — not hand-written. The generated files SHALL be committed, carry a "generated — do not edit" header naming their source, and SHALL be checked in CI: `docs:generate --check` SHALL fail when the committed pages differ from a fresh generation.

#### Scenario: A validator change shows up in the docs
- **WHEN** a limit, token or DSL rule changes in the packages and `docs:generate` runs
- **THEN** the corresponding Reference page SHALL change accordingly, with no hand edit

#### Scenario: Stale generated pages fail CI
- **WHEN** a change alters a source constant without regenerating
- **THEN** `docs:generate --check` SHALL exit non-zero naming the stale page(s)
