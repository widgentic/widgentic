## Context

See proposal.md. `injectDesignerStyles` (`packages/designer/src/dom.ts`) writes one `<style data-widgentic-designer="chrome">` into `document.head`: a `.wgd-root { --wgd-*: … }` light block, a `prefers-color-scheme: dark` block on `.wgd-root:not([data-wgd-theme="light"])`, a `.wgd-root[data-wgd-theme="dark"]` block, then the component rules. `shell.ts` and the three standalone designers create the root and set `data-wgd-theme` from `appearance`; `element.ts` reads `appearance` once in `connectedCallback`. Colours are tokenised except five dead `var(--wgd-…, #hex)` fallbacks and the menu's `rgba()` shadow; the preview surface carries dead `var(--wg-bg, #ffffff)`/`var(--wg-fg, #1f2430)` fallbacks (the preview injects the widget base stylesheet, which defines every `--wg-*` at `:root`). Typography inventory (2026-08-28, no fonts are set from JS): two families — `system-ui, sans-serif` on the root, `ui-monospace, monospace` on 16 rules (JSON panes, textareas, test output, and every code-ish value in structured rows: tags, paths, attr names, schema property names, record keys, token names/inputs) — and a four-step size scale: 13 px (root, JSON source pane), 12 px (15 rules: compact row inputs/selects, field labels, diagnostics, menu items, test output), 11 px (11 rules: badges, tags, icon buttons, inline meta, small add-buttons), 10 px (2 glyphs: the collapse chevron, the preview's "⚡ action" badge). Radii: 3, 4, 6 px and the spinner's `50%`. Mono elements take the size of the row they sit in — size is a density axis orthogonal to family, which is why "button size" and "code size" do not describe the usage.

## Goals / Non-Goals

**Goals:** a host can theme the chrome with a supported option; defaults byte-for-byte unchanged; no new dependency; the token list is a reviewed export; the stylesheet is provably token-only outside its declaration blocks.
**Non-Goals:** per-instance stylesheets, shadow DOM, a theming UI for the chrome, changing the widget preview's theming, changing layout or spacing beyond the root gap, observing later attribute changes on the elements.

## Decisions

1. **Inline custom properties on the root, not per-instance `<style>` blocks.** `root.style.setProperty("--wgd-<token>", value)` at mount wins over every class and media-query rule (the style attribute outranks any selector in the author origin), needs no id plumbing, and disposes with the root. Scheme-following is the host's job through `var()` references — the designer has no scheme logic to add. Alternative — generating a scoped stylesheet per instance for `{ light, dark }` maps — rejected: more surface, and it duplicates what host tokens already do.
2. **`applyChrome(root, chrome)` in `dom.ts`, shared by the four factories.** Filters keys against `CHROME_TOKENS` (a `readonly` tuple; `ChromeToken = typeof CHROME_TOKENS[number]`; `ChromeOptions = Partial<Record<ChromeToken, string>>`), ignores unknown keys and non-string values, and uses the CSSOM (`setProperty`) — a value cannot escape its declaration, so no sanitisation beyond "is a string" is needed; the host page is trusted by definition. **CSS-wide keywords are ignored** (`inherit`, `initial`, `unset`, `revert`, `revert-layer`, case-insensitive): on a custom property they act on the property itself — `--wgd-font: inherit` inherits the token from the parent, where it is undefined, so `font-family: var(--wgd-font)` becomes invalid at computed-value time and falls to `unset`; that happens to inherit for `font-family` but resets `radius`/`gap` to their initial values. Hosts that want their own typeface pass their variable with a fallback stack: `font: "var(--host-font, system-ui, sans-serif)"`.
3. **Element attribute `chrome` = JSON**, parsed once at connect by `parseChromeAttribute` (`try/catch` → defaults; a non-object → defaults), consistent with `appearance`, which is also read once at connect. Later attribute changes are not observed for either — documented, not a scenario.
4. **Tokenise the literals with defaults in the same `.wgd-root` block** (scheme-independent, so the dark blocks stay colour-only): `--wgd-font: system-ui, sans-serif`, `--wgd-font-mono: ui-monospace, monospace`, `--wgd-font-size: 13px`, `--wgd-font-size-sm: 12px`, `--wgd-font-size-xs: 11px`, `--wgd-radius-sm: 3px`, `--wgd-radius: 4px`, `--wgd-radius-lg: 6px`, `--wgd-gap: 16px`, `--wgd-shadow: 0 4px 14px rgba(0, 0, 0, 0.25)`. Every `font-family: ui-monospace, monospace` becomes `var(--wgd-font-mono)`; 13/12/11 px become the three size tokens; the two 10 px glyph sizes become `calc(var(--wgd-font-size-xs) - 1px)` so the defaults stay identical without a fourth token; the two `font:` shorthands keep the shorthand form with token values (`font: <size-token> <family-token>` — replacing them with longhands would stop resetting `line-height`/`weight` on the preview badge); radii 3 → `radius-sm`, 4 → `radius`, 6 → `radius-lg`; the spinner's `border-radius: 50%` is a shape (a circle), not a radius step, and stays; `.wgd-root` `gap` and `.wgd-menu` `box-shadow` read their tokens. The five `--wgd-*` hex fallbacks and the preview surface's two `--wg-*` fallbacks are deleted as dead code. Highlight colours stay tokens the host may override (they are in `CHROME_TOKENS`), defaults unchanged. Two families and three sizes were chosen over "one size plus `calc()` offsets" so a host can tighten compact rows independently of the base size.
5. **Tests:** (a) mount with `chrome` → assert `root.style.getPropertyValue("--wgd-bg")` etc. (incl. a `var()` value), and that unknown keys, non-string values, CSS-wide keywords and invalid attribute JSON leave nothing set; (b) a stylesheet audit that strips the three token blocks and asserts, structurally, that no `#hex`/`rgb(`/`hsl(` colour, no `font-family:`/`font:` with a typeface literal, no `font-size:`/`font:` with a `px` literal and no `border-radius:` with a `px` literal remains — the guard is "only tokens outside the blocks" (keywords such as `transparent`, `currentColor`, `inherit`, `none` and the spinner's `50%` are not literals of those kinds); (c) a defaults check that the `.wgd-root` token block declares exactly the documented values, so tokenising cannot drift them; (d) a computed-value check in headless Chrome (happy-dom does not cascade `var()`): a page mounting a designer with a `chrome` map reports `getComputedStyle` of the root, an input and a tag matching the map — recorded in `TESTING.md`; (e) `tools/exports.test.ts` snapshot gains `CHROME_TOKENS`.
6. **Changeset: `minor` for `@widgentic/designer`** ("designers accept `chrome` tokens; typography, radii and the menu shadow are tokens; dead fallbacks removed") — the linked group publishes 0.2.0 together.

## Risks / Trade-offs

- [A token rename later breaks hosts silently] → the list is an exported constant snapshotted by `exports.test.ts`; renames are spec changes.
- [Hosts pass garbage values] → the CSSOM rejects invalid values (property left unset → default); nothing throws; CSS-wide keywords are filtered before they reach the CSSOM.
- [Defaults drift while tokenising] → the defaults check (5c) pins the token block values; the headless-Chrome check compares computed values of an untouched designer before and after.
- [`calc()` on the two glyph sizes ties them to `font-size-xs`] → intended: a host shrinking badges shrinks the glyphs with them; nobody themes a chevron on its own.

## Migration Plan

Release 0.2.0 → in `widgentic/apps`: bump `@widgentic/designer` to `^0.2.0`, declare `--host-font` beside the other host tokens, replace the `#app-view .wgd-root` override with `chrome: { bg: "var(--host-bg)", panel: "var(--host-panel)", border: "var(--host-border)", line: "var(--host-line)", text: "var(--host-text)", muted: "var(--host-muted)", accent: "var(--host-accent)", "accent-bg": "var(--host-accent-soft)", "accent-line": "var(--host-accent-line)", danger: "var(--host-danger)", "danger-bg": "var(--host-danger-bg)", "danger-line": "var(--host-danger-line)", hover: "var(--host-hover)", font: "var(--host-font, system-ui, sans-serif)" }` on the four mounts, deploy, verify the computed chrome in both schemes.
